# PPTX 제작·검수 절차

## 1. 사전 확인

1. 연결된 작업 폴더와 적용되는 `AGENTS.md`를 읽는다.
2. 입력 자료, 디자인 기준, 아웃라인, 저장 폴더가 실제로 존재하는지 확인한다.
3. 원본과 결과물의 경계를 구분한다. 원본은 읽기 전용으로 사용한다.
4. 최종 파일과 같은 이름이 이미 있으면 덮어쓰거나 자동으로 이름을 바꾸지 말고 충돌 경로를 보고한다.
5. 지정 폴더 밖에 미리보기·로그·임시 파일을 만들지 않는다. 임시 작업물이 필요하면 허용 위치와 삭제 계획을 제작 계획에 포함한다.

## 2. 근거 범위 고정

- 원자료에서 다루도록 지정된 범위만 사용한다.
- 콘텐츠 브리프와 아웃라인의 주장마다 원자료 파일과 쪽수를 연결한다.
- 원자료에 없는 수치나 사례를 시각적으로 그럴듯하게 만들지 않는다.
- 출처를 확인하지 못했으면 추정하지 않고 `확인 필요`로 표시한다.
- 외부 자료 사용이 금지되었으면 웹 검색, 외부 이미지, 통계 추가를 하지 않는다.

## 3. 제작 전 계획

사용자에게 다음을 한국어로 먼저 보여준다.

- 작업 대상과 원자료 범위
- 예상 슬라이드 수와 도입 → 핵심 개념 → 예시 → 활동 → 정리 흐름
- 슬라이드별 메시지와 시각화 방식
- 디자인 기준의 색상·간격·구성을 16:9에 적용하는 방법
- 지정 글꼴의 실제 사용 가능 여부
- 편집 가능한 도형·도표·차트 계획
- 저장 예정 절대경로와 임시 작업물 위치
- 사람의 판단이 필요한 사항

승인이 필요한 작업이면 이 단계에서 멈추고 기다린다.

## 4. 디자인 변환 판단

- 슬라이드 크기는 16:9로 설정한다.
- 제목은 28pt 이상, 본문은 18pt 이상으로 한다.
- 슬라이드 하나에 핵심 메시지 하나만 둔다.
- 웹 화면용 px·CSS 규칙은 슬라이드 비율과 pt 단위에 맞게 변환한다.
- hover, sticky, blur, 반응형 동작처럼 정적 슬라이드에서 재현할 수 없는 규칙은 그대로 모방하지 않고 `확인 필요`로 분류한다.
- 색상, 여백, 카드, 표, 이미지 구성은 사용자가 지정한 디자인 기준만 사용한다.
- 밝은 강조색은 정보 위계가 필요한 최소 요소에 사용하고 장식만을 위한 반복을 피한다.
- 한글 가독성이 떨어지는 자간·행간·대비는 원래 의도를 유지하는 범위에서 조정하고 그 판단을 계획에 기록한다.

## 5. 글꼴 판단

1. 지정 글꼴 파일 또는 시스템 등록 상태를 읽기 전용으로 확인한다.
2. 글꼴 이름만 확인하지 말고 실제 렌더링 도구에서 해당 글꼴을 불러올 수 있는지 시험한다.
3. 글꼴 파일을 직접 등록해 정상 렌더링할 수 있으면 그 방식을 사용한다.
4. 사용할 수 없으면 다른 글꼴을 적용하지 않는다. 지정 글꼴, 실패 이유, 가능한 대체 글꼴을 `확인 필요`로 보고하고 승인 전 제작을 멈춘다.
5. 저장 후 PPTX 내부의 실제 글꼴 표기를 다시 검사한다.

## 6. 슬라이드 제작

- 제목, 본문, 도형, 흐름도는 가능한 한 편집 가능한 개체로 만든다.
- 차트가 필요한 경우에만 원자료의 검증된 수치를 사용해 편집 가능한 차트로 만든다.
- 수치 자료가 없으면 차트를 억지로 만들지 말고 편집 가능한 도형·표·다이어그램을 사용한다.
- 아웃라인의 핵심 메시지, 발문, 시각자료 방향, 출처 범위를 유지한다.
- 화면 밖 배치와 의도하지 않은 겹침을 막기 위해 안전 여백을 둔다.
- 자동 축소에 의존하기보다 텍스트 길이, 상자 크기, 줄바꿈을 직접 조정한다.

## 7. 발표자 노트

모든 슬라이드 노트에는 다음 세 항목만 이 순서로 기록한다.

```text
발표 스크립트
완결된 한국어 문장 3~5문장

교사 발문
학생에게 던질 질문 1~2개

[Sources]
실제로 사용한 파일명·경로·쪽수 또는 확인한 URL
```

- 슬라이드 문구를 그대로 복사하지 않는다.
- 예상 응답, 오개념, 진행 팁 등 네 번째 항목을 추가하지 않는다.
- 출처가 없으면 `[Sources] 해당 없음`이라고 쓴다.
- 확인하지 못한 출처는 만들어 내지 않는다.

## 8. 렌더링 검수

1. 저장 전 또는 저장 직후 전체 슬라이드를 이미지로 렌더링한다.
2. 전체 모아보기로 흐름, 색상, 밀도, 반복성을 확인한다.
3. 각 슬라이드를 원본 크기로 열어 다음을 전수 검사한다.
   - 제목과 본문의 잘림
   - 도형과 텍스트의 겹침 순서
   - 화면 밖 요소
   - 지나치게 작은 글자
   - 대비와 한글 가독성
   - 정렬, 간격, 카드 크기의 일관성
4. 문제가 있으면 최소 범위로 수정하고 PPTX를 다시 만든 뒤 전체를 다시 렌더링한다.
5. 첫 렌더링 성공만으로 검수를 끝내지 않는다.

## 9. 구조 검증

- 파일이 실제로 존재하는지 확인한다.
- PPTX를 다시 열 수 있는지 검사한다.
- 슬라이드 수와 16:9 비율을 확인한다.
- 모든 슬라이드에 발표자 노트가 있는지 확인한다.
- 각 노트의 스크립트 문장 수, 발문 수, `[Sources]` 존재 여부를 전수 검사한다.
- PPTX 내부 글꼴이 지정 글꼴인지 확인한다.
- 넘침 검사 도구가 있으면 실행한다.
- 검증 보조 파일과 임시 작업물은 승인된 범위에서 제거한다.

## 10. 완료 보고

완료 보고는 한국어 표로 작성한다.

| 항목 | 보고 내용 |
|---|---|
| 생성한 파일 | 실제 파일명과 최종 절대경로 |
| 원본 상태 | 수정·이동·삭제 여부 |
| 검증 결과 | 재열기, 슬라이드 수, 16:9, 글꼴, 노트, 렌더링 결과 |
| 편집 가능성 | 도형·표·차트가 편집 가능한지와 차트 미사용 사유 |
| 확인 필요 | 검증하지 못한 사항과 사람의 판단이 필요한 항목 |

계획 경로를 실제 결과처럼 보고하지 않는다. 실제 파일 존재를 다시 확인한 뒤 최종 절대경로를 기록한다.
